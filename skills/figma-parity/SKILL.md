# Figma parity

Load the `build-rules` skill first and follow it throughout.

Build what the frame draws and nothing it leaves out. There are two phases: capture the
reference before the build, then compare after it. A passing build or a screen that looks close
does not count as parity. The comparison does.

## 0. Check the tools

This skill needs the Figma MCP server. Check that Figma tools are available (for example
`get_design_context` and `get_screenshot`). If they are missing, tell the user how to add it:

```bash
claude mcp add --transport http figma https://mcp.figma.com/mcp
```

In Codex, the user adds the same server in the Codex MCP settings. The user signs in to
Figma in the browser window that opens. Stop until that is done.

Phase 2 needs Playwright. If `npx playwright --version` fails, say how to install it:
`npm i -D @playwright/test`, then `npx playwright install chromium`.

## 1. Capture the reference (before the build)

Take the file key and node id from the URL: `figma.com/design/FILE_KEY/NAME?node-id=12-34`
(the node id is `12:34`). A URL with no `node-id` is not enough. Ask for the link to the
specific frame.

Save to `.build-loop/parity/<screen>/`:

| File | Content |
|---|---|
| `reference.png` | Screenshot of the frame at its drawn size |
| `spec.md` | Every text string exactly as drawn, colors (hex), fonts and weights, font sizes and line heights, spacing, corner radii, and the width and height the frame is drawn at |
| `states.md` | Every other state the file draws for this screen (empty, error, loading, hover, filled), each with its own screenshot |

Rules for the capture:

- Download screenshots right away. Their links expire.
- If the frame is drawn at more than one size (phone and desktop), capture each one and note
  the widths.
- Note what the frame leaves out (no search box, no footer, no dark mode). The build leaves
  those out too.
- Treat code generated by the tool as a reference to adapt. Use the project's own components
  and colors where they match, and record each place where they differ from the frame.
- If the file holds several versions of the screen, ask the user which one is final.

## 2. Build

Hand `spec.md` to the build. Each text string, color and size in the spec is used as drawn.
Each state in `states.md` is built.

## 3. Compare (after the build)

Start the app with the project's dev command. Take a Playwright screenshot at each size the
frame is drawn at:

```bash
npx playwright screenshot --viewport-size=390,844 --full-page http://localhost:3000/PATH .build-loop/parity/SCREEN/built-390.png
```

Replace the size, port, path and screen name with the real values from the spec. If the screen
needs a signed-in user, sign in with a test account first.

Then read both images yourself. Judge text from full-size crops of each region (header, each
card, each button, the footer), cut from the frame image and the built image at the same
bounds. A shrunken full-page view hides wrong words and small shifts. Check, one by one:

- Text content, spelling, capital letters and line breaks.
- Colors, borders, shadows and corner radii.
- Font, weight, size and line height.
- Spacing, alignment and the size of each element.
- Every state in `states.md`.
- Anything on the built screen that the frame does not draw.

Never screenshot a screen that shows a secret.

## 4. Write the comparison

Write `.build-loop/parity/<screen>/comparison.md` as a table:

| Element | Frame draws | Built screen has | Change |
|---|---|---|---|

Each row names the exact change, for example: button label reads `Save`, the frame says
`Save changes`. Put the verdict first: matches, or N differences. After fixes, take the
screenshots again and update the table. A difference is closed when the new crop shows it.

## Report to the user

- Matches, or the count of differences left.
- The three differences that matter most, in plain words.
- The path to `.build-loop/parity/<screen>/`.
- Which sizes and states were checked, and which were not.

Fixes use the build gates. **Stop** after the report. The user says when to fix and push.
